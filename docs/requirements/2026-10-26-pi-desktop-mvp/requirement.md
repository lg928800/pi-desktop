# pi-desktop MVP — 需求与设计草案

- 状态：**设计细化，待评审**（2026-10-26）
- 模块：`ui` / `bridge` / `ext-*`（pi 扩展），待 P0 后定稿
- 关联：`../../HANDOFF.md`

## 1. 背景

pi 是终端 agent，三个体验瓶颈：

1. 长会话/长 diff 在终端里难以回看；
2. 多任务并行只能开多个终端，状态不可见；
3. 危险操作只能"看着它跑"，事后无记录。

同类桌面端（Conductor / Vibe Kanban / Crystal / Cursor）已验证「任务 ↔ 目录 ↔ 会话」三元绑定成立。

## 2. 目标 / 非目标

**目标**
- 一次 agent 任务的全生命周期可视：层级归属 → 对话 → 计划 → 审批 → 落地。
- 多任务并行，单会话崩溃不影响其他。
- 改动可控、可审计：谁批准的、改了什么、什么时候落地。

**非目标**
- 自建 agent 引擎或模型接入层（pi 已解决）
- 云端同步、多账号、插件市场、移动端
- 完整代码编辑器（diff 只做展示与审批，不做编辑）

## 3. 信息架构

### 3.1 左侧：四级层级树

```
项目 Project            ← 一个本地目录 / git 仓库；绑定 AGENTS.md、默认模型、默认权限策略
 └ 功能集 Feature Set   ← 一轮目标（如「登录重构」），可跨多个任务；有验收标准
    └ 任务 Task         ← 一次性交付物；绑分支/worktree、文件挂载、权限策略、验收标准
       └ 会话 Session   ← 一次实际执行的对话；可 fork 成多个「尝试」
```

设计要点：
- **层次是归属，不是文件夹**。会话不靠路径猜归属，靠任务元数据显式声明。
- **会话可 fork**：pi 的 session tree 天然支持分叉，一个任务下允许多个尝试并行比较，最后择优落地。
- **挂载文件有三种语义**，必须区分（否则容易误删东西）：
  - `context`：只作上下文（读出内容注入 prompt），不可改；
  - `working`：工作集，允许修改；
  - `protected`：明令不可触碰（实现参考 pi 的 `protected-paths.ts` 扩展）。
- 正交维度（不占层级）：状态、标签、优先级、里程碑/迭代、归档、任务模板。

### 3.2 中间：对话层

流式消息 + 工具调用卡片（read/edit/bash 各自渲染）+ 输入框 + 中断。
工具卡片可折叠成一行，展开看完整参数/输出/diff。

### 3.3 右侧：进度与落地（可折叠）

不是"又一个信息栏"，而是**这次任务到底做到哪了、能不能收工**的判据：

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 阶段 | 探索 / 计划 / 执行 / 待审批 / 待落地 / 已完成 | 会话事件 + 状态机 |
| 计划步骤 | 步骤列表 + 完成标记（`[DONE:n]`） | agent 输出，扩展解析 |
| 变更清单 | 文件 + 增删行数 + 是否越界 | git diff（bridge 独立采集） |
| 待审批队列 | 等待人工决定的动作 + 倒计时 | 审批 gate 日志 |
| 风险命中 | 危险命令、受保护路径被触、范围外修改 | gate + diff 对账 |
| 指标 | 耗时、token、成本、工具调用次数 | `get_session_stats` |
| 落地区 | commit message 草稿、分支、diff 预览、[落地] [丢弃] [继续改] | bridge 的 git 模块 |

**核心机制：三轨对账。**
- 意图轨（agent 说它要干什么 / 干完了什么）
- 实际轨（git 与工具调用记录的客观事实）
- 审批轨（人批准了什么）

两轨不一致就标红（例：计划说改 3 个文件，git 显示 5 个；或改了 `protected` 文件）。**不允许只显示 agent 的自述**——这是本项目的可信度底线。

## 4. 权限模型

先拆开两件常被混为一谈的事：

| | 干活时的审批 | 落地时的审批 |
| --- | --- | --- |
| 时机 | agent 调工具前 | 任务结束时 |
| 对象 | 单个动作（bash 命令 / 写文件） | 整体改动（diff / commit） |
| 实现 | pi 扩展的 `tool_call` 网关（`{ block: true }`） | bridge 的 git 模块，agent 无权自动执行 |

**四档策略（可按项目 → 功能集 → 任务逐级覆盖）**

| 档位 | 行为 | 适用 |
| --- | --- | --- |
| L0 只读探索 | 禁 `edit`/`write`，`bash` 限白名单命令 | 摸代码、评估 |
| L1 危险操作审批 | 破坏性/写入/联网动作逐个确认 | **默认** |
| L2 自动执行 + 落地前审批 | agent 自由改，人不盯过程，收工时看 diff 决定是否 commit | 信任的仓库、常规重构 |
| L3 全自动 | 连落地也自动（自动 commit），仅事后看报告 | 自用、低风险脚本类 |

可再细化到动作类别：文件写、文件删、bash、网络、git 写操作、MCP 工具。

**两条硬规则：**
1. **UI 不在场必须 fail-closed**。审批弹窗无人应答 → 阻塞该动作，绝不默认放行。
2. 策略命中"要审批"时，阻塞的是**那个 tool call**（agent 会等），因此 UI 必须显示倒计时与"进程仍在等待"的状态，防止误以为卡死。

## 5. 架构

```
┌ 壳 Tauri 2（窗口/托盘/全局快捷键/通知）
└ UI (React + TS + Vite)
     │  WebSocket 127.0.0.1 + 一次性 token
  Bridge (Node sidecar)          ← 唯一后端
     │            ├─ 任务/层级元数据（本地 JSON 文件，非数据库）
     │            ├─ git 模块（diff / commit / 落地审批）
     │            └─ 三轨对账
     │  stdin/stdout JSONL
  pi 子进程 × N（`pi --mode rpc`，一个会话一个进程）
     └ 扩展：权限网关 / 计划进度 / 受保护路径
```

- 一个会话一个子进程：RPC 是单会话模型（`switch_session` 顺序切），并行必须多进程；崩溃隔离是附带收益。
- **无数据库**：会话内容以 `~/.pi/agent/sessions/**.jsonl` 为唯一事实源；任务层级是我们的 UI 元数据，落本地 JSON。
- **不动 pi 源码**：权限、计划进度、受保护路径全部用 pi 官方**扩展**机制实现（`tool_call` 钩子 + `ctx.ui.confirm`，RPC 模式下自动变成 `extension_ui_request` 给我们的 UI）。

## 6. 技术选型

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 集成方式 | `pi --mode rpc` 子进程 | 官方为自定义 UI 设计的通道；语言无关；进程隔离 |
| 是否 fork pi | **否** | TUI 是 ANSI 渲染，改 Web 等于重写；fork 要无限期 rebase；能力缺口用扩展补 |
| 外壳 | **Tauri 2**（macOS WKWebView） | ~10-20MB；窗口/托盘/全局快捷键可定制；长期自用不背 150MB |
| 语言 | TypeScript 全栈（壳层少量 Rust） | 与 pi 同生态 |
| 渲染 | React + 虚拟滚动 | 单会话可达数 MB / 上千条消息（实测最大 9.3MB） |

## 7. 可直接复用的 pi 官方示例（省 60% 造轮子）

| 需求 | 参考实现 |
| --- | --- |
| 权限审批 | `examples/extensions/permission-gate.ts`、`confirm-destructive.ts`、`timed-confirm.ts` |
| 计划步骤 + 完成标记 + 进度 | `examples/extensions/plan-mode/`（`[DONE:n]` 标记、只读模式、白名单 bash） |
| 任务清单状态（分支安全） | `examples/extensions/todo.ts`（状态存 tool result details，天然跟随分叉） |
| 受保护路径 | `protected-paths.ts` |
| 落地/回滚 | `git-checkpoint.ts`、`auto-commit-on-exit.ts`、`dirty-repo-guard.ts` |

**迁移成本（别低估）**：这些示例的**状态逻辑可直接用**，但渲染是 TUI 组件（`@earendil-works/pi-tui`），在 RPC 模式下 `ctx.ui.custom()` 不可用、`setWidget` 只发通知不发数据。所以：**逻辑复用，渲染重写**，并把状态改为经 `get_entries` 或扩展自定义事件送到 UI。

## 8. 五个技术难点

1. **流式渲染**：`text_delta` 增量拼接，`message_end` 到达时用权威消息整体替换；结束用 `agent_settled`（不是 `agent_end`）。
2. **帧解析**：字节流按 `\n` 切；禁用 `readline`（会误切 `U+2028`/`U+2029`）。
3. **审批流**：`extension_ui_request` 的 `confirm`/`select` → 非阻塞弹窗队列 + 倒计时；UI 断线 fail-closed。
4. **长会话性能**：虚拟滚动 + 旧消息折叠。
5. **进程生命周期**：UI 刷新/断线不杀 agent；重连用 `get_messages` + `get_state` 重建现场。

## 10. 安全底线

- WebSocket 仅绑 `127.0.0.1` + 一次性 token，拒绝非本地来源。
- 审批默认开启且留痕（谁、何时、批准了什么）。
- 密钥只在 pi 的 `auth.json`，Bridge/UI 不接触明文。
- 无"隐藏的全自动"开关；L3 必须显式选择并在 UI 上常驻标识。
- 落地（commit）只能由人触发，agent 无权限。

## 12. 跨平台（macOS / Windows / Linux）

Tauri 2 三端可用，但**每个系统用的 webview 不同**：macOS WKWebView、Windows WebView2、Linux WebKitGTK。这决定了三条纪律：

1. **只用标准 Web API**，不依赖 Chromium 私有特性；复杂 CSS（backdrop-filter、高级滚动）先在 WebKit 验证——macOS 本身就是 WebKit，本地先跑 Safari 内核等价于提前发现问题。
2. **快捷键必须抽象**：`Mod = Cmd(mac) / Ctrl(win+linux)`，禁在代码里写死 `metaKey`；沿用 pi 的动作命名（`app.session.new`）便于两边键位一致。
3. **平台差异集中到 `platform` 能力层**：

| 差异点 | 处理 |
| --- | --- |
| 启动 pi 子进程 | Windows 上 `pi` 实为 `pi.cmd`，需 `shell: true` 或解析真实路径 |
| 路径分隔符 / 大小写 | 只用 `node:path`，比较路径前规范化；macOS 默认不区分大小写 |
| git 是否存在 | 启动自检；缺失则禁用「落地」并明示，不静默失败 |
| 终端渲染 | ANSI 输出用 xterm.js（三端一致），不自绘 |
| 托盘/菜单 | 各自原生；Linux 部分桌面环境不显示托盘，需有菜单栏兜底 |
| 打包 | mac 公证、Win 签名、Linux AppImage/deb；自用阶段只做未签名构建 |
| Linux 依赖 | WebKitGTK 4.1 + libsoup3，在 README 写清安装命令 |

## 13. 多模态

协议层已经够用：`prompt` / `steer` / `follow_up` 都接受 `images: [{type:"image", data: base64, mimeType}]`；`get_available_models` 返回每个模型的 `input: ["text","image"]`。

设计要点：

1. **能力门禁**：选模型时读 `input` 字段，不支持图片的模型禁用附件按钮并说明原因；切换模型时若历史里有图片而新模型不支持，提示而非静默丢图。
2. **三条入口**：粘贴（剪贴板）、拖拽、文件选择。
3. **体积控制**：base64 走 WebSocket 会放大 33%。bridge 侧限制单图原始 ≤ 8MB、单条消息 ≤ 4 张，超出先降采样再送；pi 自身也有 `images.resize` 缓存安全档位。
4. **渲染**：会话里的 `ImageContent` 显示缩略图，点击看原图；不要把 base64 塞进 DOM 属性反复重绘。
5. **副作用提醒**：图片以 base64 写入会话 jsonl，会显著撑大会话文件（普通文本会话最大实测 9.3MB）。需在设置里提供「会话保留策略」，并在会话体积超阈时提示。
