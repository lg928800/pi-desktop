## 0. 一句话现状

**能把 AI 干活的过程看明白的桌面客户端**（骨架稳、协议清、视觉可用），
**还不是能放心让它干活的工具**——差两件：**拦得住危险动作**、**改完能验收落地**。

## 1. 🔴 P0：不做就不该拿去跑真仓库

### 1.1 权限网关（最高优先）

| | |
|---|---|
| 现状 | 完全没实现。UI 有审批弹窗、bridge 有 `approval.reply` 通道、`extension_ui_request` 映射也在，但**没有任何扩展去发审批**，pi 想 `rm -rf` 就直接执行 |
| 影响 | 这是唯一的安全阀。当前使用要求"人始终盯着"，等于把终端里的风险原样搬到桌面 |
| 方案 | `extensions/permission`：`pi.on("tool_call")` 返回 `{ block: true }`；四档策略 L0 只读 / L1 危险审批 / L2 自动+破坏性审批 / L3 全自动；判定优先用 `annotations.destructiveHint`，其次内置正则 |
| 验收 | ① L0 下 `edit/write` 被拒且 bash 白名单外被 block；② L1 下 `rm -rf` 弹窗，拒绝则命令不执行；③ UI 断线时该调用阻塞而不是放行（fail-closed）；④ 真 pi 上跑通一整轮（不是假子进程） |
| 量级 | 1 天 |

### 1.2 附件三语义

| | |
|---|---|
| 现状 | `context`（只读上下文）/ `working`（可改）/ `protected`（禁碰）只有类型定义，UI 不能选、网关不校验 |
| 影响 | 用户以为"只给它看这个文件"，实际 agent 能改全仓库 |
| 验收 | 任务详情能挂载文件并选语义；写 `protected` 文件时被网关拦截并告知 |
| 量级 | 随 1.1 一起做（半天） |

### 1.3 会话持久化

| | |
|---|---|
| 现状 | `state.sessions.sessionFile` 恒为 `null`；会话只在活进程里，bridge 重启后点任务是**新开会话**，上下文全丢 |
| 影响 | 关一次窗口就断片，长期使用不可接受 |
| 方案 | 启动时 `get_state` 拿 `sessionFile` 写回 state；重开时用 `--session <file>` 接回；session 文件索引扫描 `~/.pi/agent/sessions/**.jsonl` |
| 验收 | 开会话 → 聊两轮 → 杀掉 bridge → 重启 → 点同一任务仍能看到历史并继续 |
| 量级 | 半天 |

## 2. 🟠 P1：产品完整性

| # | 缺口 | 现状 | 验收标准 |
|---|---|---|---|
| 2.1 | 落地（commit） | 无 git 模块、无 diff 视图 | 任务结束能预览 `git diff`、填 commit message、点「落地」才提交；agent 无权自动提交 |
| 2.2 | 三轨对账 | 右栏只有状态与计数 | 计划（意图）/ git（实际）/ 审批记录 三者对比，不一致标红（越界改动、protected 被碰、无人批准的动作） |
| 2.3 | 长会话性能 | 无虚拟滚动，DOM 全量渲染 | 回放 1000 条消息滚动不掉帧（>50fps） |
| 2.4 | 多会话并行 UI | 后端会话池已支持多进程 | 能同时看两个会话并切换，事件不串台，崩一个别的继续跑 |
| 2.5 | 思考档位 / 上下文用量 | 都没接 | 能切 thinking level；显示 token/成本/剩余窗口（`get_session_stats`） |
| 2.6 | 图片接收 | 只显示 chip，无缩略图；历史回放丢图 | 缩略图渲染 + 点击看原图；历史里图片也在（走 `asset.get`） |
| 2.7 | 断线重连 | 断线只改状态，需手动重连 | 自动重连并用 `get_messages` 恢复现场 |
| 2.8 | 审批审计落盘 | 只在内存 | 谁、何时、批准了什么，可导出 |

## 4. 扩展路线（产品向）

按"用户价值 / 实现成本"排序，前三条建议与 P0/P1 一起排期。

| 优先 | 功能 | 价值 |
|---|---|---|
| ★★★ | **计划步骤面板** | 复用 pi 的 `plan-mode`，右栏出 `[DONE:n]` 勾选，进度从"感觉"变"证据" |
| ★★★ | **会话 fork 对比** | 同任务两种方案并行，左右摆 diff 择优落地（pi 的 session tree 原生支持，成本低收益高） |
| ★★ | **worktree 隔离** | 同时跑多分支任务互不污染 |
| ★★ | **项目资源管理** | UI 里编辑 AGENTS.md、开关 skills / MCP（现在只能敲 `pi config`） |
| ★★ | **历史检索** | 扫 jsonl 建索引，跨项目搜"上次那个接口怎么改的" |
| ★ | **任务看板** | 卡片拖拽驱动状态机，比聊天列表更符合"派活"心智 |
| ★ | **任务模板** | "跑测试→修→提交"这类固定流程一键复用 |
| ★ | **多模型对比** | 同一 prompt 并发两个模型比结果 |
| ★ | **成本仪表 / 通知 / 语音输入** | 体验补强 |

## 5. 已知限制（当前版本请知悉）

1. **危险命令不会拦**：权限网关未实现前，别在真实仓库里让它执行删除/推送类操作。
2. **仓库不能挪**：`.app` 通过编译期路径找仓库里的 bridge 源码，删/移动 `~/onlyProject/pi-desktop` 后窗口能开但连不上后端。
3. **重启即失忆**：bridge 退出后会话上下文不保留（见 1.3）。
4. **跨平台未验证**：Windows/Linux 只有代码层兼容，没有实机验证。
5. **打包目标**：当前 `bundle.targets = ["app"]`，DMG 因本机挂载冲突暂时关掉。

## 6. 已定且不建议推翻的决策

| 决策 | 理由 |
|---|---|
| 不 fork pi 源码 | TUI 是 ANSI 渲染，改 Web 等于重写；RPC 是官方给自定义 UI 留的口子；能力缺口用扩展补 |
| 不建数据库 | 会话以 `~/.pi/agent/sessions/**.jsonl` 为唯一事实源，我们只存层级元数据，避免双写不一致 |
| 「干活审批」与「落地审批」分离 | 前者是工具级拦截（扩展），后者是整体 diff 审核（bridge），混在一起会既难用又难审计 |
| 三轨对账 | 右栏不允许只复述 agent 自述，必须与 git 事实对照 |
| 过程/结果分离 | 过程给证据（终端流），结果给结论（Markdown 卡片） |
| 审批 fail-closed | UI 不在场时阻塞，绝不默认放行 |
